## 3. P6 音频验收

### 3.1 通路

`SD 卡 WAV` → M0 逐扇区读 → AHB 写 32 bit（**一个字 = 两个连续 16 bit 样本**）→ 512×32 异步 FIFO → 采样时钟 `samp_tick`（`AU_RATE` 分频，默认 1134 → 44 092 Hz）→ 可选 high-shelf → 数字音量 → **sigma-delta（默认）或 8 bit 噪声整形 PWM** → `audio_pwm`（F3）→ LMV358 二阶低通 → FM8002A 类 D 功放 → 3.5 mm / 喇叭座。麦克风是独立通路：MIC → LMV358 前级 → SPI ADC（J6/K5/H3/G6，100 kSPS）→ 仅送频谱柱，**不进功放**（不会啸叫）。

### 3.2 结果

| 项 | 结果 | 证据 |
|---|---|---|
| SD 卡 exFAT WAV 流式播放 | ✅ | 44.1 kHz/16 bit/立体声，折叠单声道后 44.1 kSPS，FIFO 512 字 ≈ 11.6 ms 缓冲，实测无欠载 |
| 曲目循环、语音单次 | ✅ | 音乐到末尾自动重播；角色语音 `mt_once` 只播一遍 |
| 音质 | ✅（可接受） | 修掉半速、FIFO 被 `au_level()` 恒 0 卡死、CTRL 只写寄存器误清使能等 6 个 bug 后可清晰听出原曲 |
| 底噪 | ✅ | 8 bit PWM 的量化底噪在 A/B 中被证实；切到 sigma-delta 后杂音基本消失（带内 SNR 提升 ~20 dB） |
| 软件高频补偿 | ✅ | 板载模拟低通的实测响应：2 kHz −10 dB / 4 kHz −19 dB / 8 kHz −37 dB；shelf（极点 ~880 Hz）分 0/+6/+12/+18 dB 四档，实测**默认 0 dB 最好** |
| 纯音自检 | ✅ | KEY5 硬件 1 kHz（完全绕开 SD/固件/FIFO），实测 1000.0 Hz、谐波占比 93–97%、>8 kHz 0.00% |
| 频谱柱 | ✅ | 8 段两极点对数带（拐点 10.5k/5.3k/2.6k/1.3k/660/330/165/82 Hz），12 dB 峰值门限，半透明叠加 |
| 麦克风驱动柱子 | ✅ | KEY1 切源；麦克风插到底后正常响应（此前"无信号"是插头未插到底） |

### 3.3 已知限制

- **模拟带宽**：板载 RC 低通的代价是 2 kHz 以上衰减严重（厂商用它压 195 kHz 载波）。软件补偿只能"抬电平"，无法恢复信噪比；听感仍是"偏闷"。要根治需改硬件（换高阶低通或 I²S DAC）。
- **轮播 + 音乐不能同时**：SPI 6.25 MHz 实测上限 ≈ 320 KB/s；壁纸 921 KB/帧 ÷ 4.07 s ≈ 226 KB/s，音乐 44.1 kHz 立体声 = 176 KB/s，合计 402 > 320。音乐播放期间壁纸停住（设计如此）。可行方案：22.05 kHz 单声道素材（44 KB/s，合计 270 ✅）或 SPI 提到 12.5 MHz（≈640 KB/s，需实测信号完整性）。

## 4. P7 角色资源包验收

### 4.1 卡结构

```
/CHARS/<角色名>/          ← 每个角色一个目录（最多识别 2 个）
    *.bmp                 ← 该角色的壁纸帧（640×480 24bit），按文件名排序播放
    voice.wav             ← 切到该角色时播一遍（可缺省）
    char.ini              ← 可选，`dwell=3` 覆盖默认停留秒数（1..60）
/<任意>.wav               ← 卡根目录的 WAV 作为音乐库（KEY7 播放第一首）
```

兼容旧布局：`CHARS` 不存在时退回扫描卡根目录的 BMP（P2 行为）。

### 4.2 结果

| 项 | 结果 | 证据 |
|---|---|---|
| 上电自动扫描角色包 | ✅ | 8 组卡（阿米娅/碧蓝航线）均自动识别，数码管先显示包数 |
| KEY9 切换角色包 | ✅ | 切换后重扫、重启轮播、播该角色语音；用户实测「卡内切换已经没有问题了」 |
| 每包独立 `dwell` | ✅ | `char.ini` 的 `dwell=` 生效（用户手动改为 3 s） |
| 换卡后不用重新烧程序 | ✅ | 同 bit/hex，换卡即换内容（方案 P7 验收口径） |
| 带电热插拔 | ⚠️ 有恢复机制 | 板上无卡检测脚：`sd_ctrl` 看门狗在传输卡住 ~21 ms 后中止并发 1.3 ms `sd_reinit`，卡 FSM 重跑 CMD0…；固件在连续 3 帧失败或音乐启动失败后 `exf_mount()` 重挂载、重扫包并重启轮播。实测可用，但恢复过程会闪一下错误码（属预期） |

坑（已修）：exFAT 目录条目组跨扇区时（18 字符文件名 = 4 条目 = 128 B，落在扇区尾 32 B 处）整组被丢弃 → 第 2 个角色包"消失"；NoFatChain 连续文件的簇号必须 `cl+1` 而不是走 FAT；文件名末尾 NUL 填充被抄进 `nm[]` 导致扩展名判断失效。

## 5. 构建与烧写

见 `P8_RELEASE.md`。要点：

1. 固件：`Start-Process D:\Keil_v5\UV4\UV4.exe -ArgumentList '-r','...m0_p2.uvprojx','-j0','-o',log -Wait`（UV4 是 GUI，`&` 会立刻返回）；产物 `m0_p2\m0_code.hex` 必须复制到 `project0\prj\p2_sd_display\m0_code.hex`（`Block_RAM.v` 的 `$readmemh` 相对源文件目录解析）。
2. bit：在 `project0\prj\p2_sd_display` 下**先删** `p2_sd_display_Runs` 与 `p2_sd_display.al`，再 `td_commands_prompt.exe run_p2.tcl`（约 100–150 s），成功的标志是日志尾出现 `P2_FLOW_DONE`。
3. 新增 `.v` 文件必须手工加进 `run_p2.tcl:6` 的 `add_files` 列表，否则不参与综合。
4. 烧写：`Mode = PROGRAM_SRAM`（易失，调试用）或 `PROGRAM_FLASH`（固化，掉电保持）。
